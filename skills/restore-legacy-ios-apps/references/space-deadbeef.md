# SPACE DEADBEEF: community case and transfer conditions

Read this case when evaluating a small custom engine, software-to-Metal rendering, native control adaptation, or a frame-rate counter that conceals uneven output. The [full report](https://github.com/DylanMcD8/respring-skill/blob/main/reports/space-deadbeef-restoration-2026-11-09.md) contains the detailed investigations and dated validation matrix. Prepared 9 November 2026; released implementation snapshot `429100c0897c79bf6230118c1915179d597a5bbc`, 8 November 2026.

The contributor reports an app-specific C++ ARMv6/Thumb interpreter that enters original gameplay below its UIKit wrapper. SwiftUI/native hosts replace exercised platform boundaries; Metal or software handles drawing. This is neither touchHLE nor AOT nor a gameplay rewrite. Consider this boundary when a symbol-rich custom game exposes tractable update/render/input entry points; do not assume it will suit exception-heavy or opaque engines. The report records narrow exception stubs, not verified throwing/unwinding. See report §§3, 5.1 and 6 before transferring that approach.

## Optional platform adaptations

Apple Watch and Apple TV are optional extensions, not default restoration targets or an initial feasibility checklist. Establish the requested iPhone/iPad experience first unless the user explicitly chose a different starting platform. Consult Crown, remote/focus, Watch executable-slice and TV storage details only when that platform is requested or already in scope. Do not add targets, run platform builds/tests, or delay the primary restoration merely because this report covers them. General timing, rendering and lifecycle lessons can still apply on the requested platform without opening a Watch/TV workstream.

## Source-reviewed lessons

The following four implementations were read at the pinned snapshot during integration. Their historical tests and measurements were not rerun.

- **Equal callback and update averages can conceal uneven output.** The [frame clock](https://github.com/ANGOmarcello/space_undeadbeef/blob/429100c0897c79bf6230118c1915179d597a5bbc/Sources/Host/GameFrameClock.swift) records callbacks, updates, submissions/images, zero-step callbacks and catch-up separately. Borrowed scheduling leeway retains negative debt; erasing it would accelerate a fast callback stream. The report describes software epoch alignment fixing paired zero-step/catch-up callbacks. Test an unfavorable initial phase and irregular callbacks, then compare actual publications. The 60 Hz baseline, 1 ms leeway and four-step cap are case values, not recommended defaults for other games. Software publication and Metal submission are not physical scanout.
- **Batch only when state, order and ownership permit it.** The [Metal renderer](https://github.com/ANGOmarcello/space_undeadbeef/blob/429100c0897c79bf6230118c1915179d597a5bbc/Sources/Legacy/SDBMetalRenderer.mm) validates every draw before encoding, including zero-length records and invalid blend values that could alias an opaque pipeline key. It merges only consecutive contiguous ranges with matching render state, never sorts transparent draws or crosses gaps. GPU completion releases each busy buffer slot. Compare overlap/additive fixtures, nonzero vertex starts and invalid records against an independent original/unbatched path. Distinguish queue backpressure from a missing shader library or invalid drawable; a broken renderer must not become a passing unsupported-device skip. Report §§5.2 and 5.6 describe parity procedures; they are historical evidence, not fresh conformance results.
- **Input accepted between simulation steps must survive until consumption.** The [Crown model](https://github.com/ANGOmarcello/space_undeadbeef/blob/429100c0897c79bf6230118c1915179d597a5bbc/Sources/Host/GameCrownInput.swift) preserves an accepted destination on idle, unwraps finite-range deltas, and reanchors reversal to the live position rather than consuming travel toward an obsolete target. Test idle-before-step, wrapped bursts, reversal and touch takeover. This is a spring-target control case, not a generic replacement for guest touch. Report §§5.7–5.8 additionally distinguish TV contacts, held button presses, menu focus, release and cancellation; simulated correctness does not establish hardware feel.
- **Audio recovery must not depend on the stopped audio path.** The [lifecycle policy](https://github.com/ANGOmarcello/space_undeadbeef/blob/429100c0897c79bf6230118c1915179d597a5bbc/Sources/Host/GameLifecycle.swift) separates scene scheduling, interaction, interruption, graph rebuild and explicit resume gates. Only successful eligible OS activation clears a stale interruption; failure remains retryable. Test a missing end event, denied-then-successful activation and stale held input across a modal. Keep a usable original Pause/Resume path. Transient-inactivity policies differ by platform; do not copy the iOS scheduling choice to every host. Report §5.9 explicitly leaves actual notification/audio-output retesting unverified.

## Additional reported techniques to investigate

These have detailed pinned references in the report but were not independently source-reviewed during integration:

- Tight glyph atlases need cell-bound sampling and nonzero draw-start fixtures. Higher-density sprite sets must preserve guest metrics, animation registration and alpha; soft gradients can need different filtering from hard contours (§§5.4–5.5).
- Native menu actions should revalidate live guest state and original hit order; canceled aim must not fire a release volley (§5.7).
- Local save acceptance, recovery, portable semantic validation and transport payloads are separate contracts. The report's KVS and Files representations have different privacy properties; inspect actual serialization rather than assuming both omit unknown bytes (§§5.11–5.12).
- Verify executable platform load commands as well as ARM64 architecture: a Simulator binary can also be ARM64. Verify per-slice minimums for older Watch hardware, then distinguish installation from visible execution (§§5.8 and 8).

Keep the original-aspect baseline, unsupported-input failures and failed experiments visible. The report supplies no original-device fidelity proof, general ISA/framework conformance, full physical timing/audio/haptics coverage, or two-device cloud-delivery result. Reported Mac proxy measurements do not become Watch hardware FPS or battery claims.
