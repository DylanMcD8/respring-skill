## 1. Executive findings and status

- **SOURCE** The original 32-bit ARMv6 machine code still owns gameplay. A bounded interpreter enters the original C++ game below its UIKit wrapper. New native hosts own input, frame scheduling, presentation, audio, and persistence. Three guarded guest instruction hooks adapt geometry. There is no static gameplay translation, general iOS emulation, JIT, or recovered original developer source. [S-CPU] [S-ENGINE] [S-GEOMETRY]
- **RECORD** The original-aspect 1.0 (1) baseline reached visible gameplay on an Apple Watch running watchOS 27 after installation and running-process readback. Earlier and later builds exercised concrete gameplay and menus on Apple silicon Mac and iPhone, iPad, TV and Watch Simulators. Later signed iPhone/Watch installs and physical TV install readbacks are separately recorded. The final 1.1 (23) unsigned iPhone/iPad release passed artifact audit and its corresponding Simulator flows. These are different builds and acceptance layers. See V01–V23 in the validation matrix.
- **RECORD** Matching the original update workload and measuring separate boundaries made two different defects visible. First, removing repeated synchronous audio work eliminated CPU deadline misses in one matched 30-second Mac workload. Later, a Watch Simulator timer produced about 60 callbacks and updates per second while publishing only 39.7–46.0 images per second in sampled gameplay windows. Aligning the software epoch corrected that mismatch. Physical scanout, device thermals, audible output quality, and worst-case later stages remain **UNVERIFIED**. See §7.
- **SOURCE / RECORD** The original 256-byte save remains the game-visible record. The host adds recoverable local transactions and two optional exchange transports. The public build's Files flow passed local two-writer tests and actual Simulator picker cancellation. Successful iCloud Drive delivery between signed devices, provisioned KVS delivery, and migration of an original installation's real save remain **UNVERIFIED**. [S-SAVE] [S-FOLDER] [S-CLOUD]
- **INFERENCE** The most reusable sequence is to preserve an exact working binary baseline, keep the host and guest contracts separate, then promote each replacement only after a targeted counterexample and an original-game transition. This follows from the opcode/state comparisons, render parity fixtures, focus/input regressions and save/relaunch evidence below.

## 3. Execution architecture and provenance

```text
SwiftUI scene and platform input surfaces
  -> GameSession: lifecycle gates, input ownership, fixed simulation clock
  -> SDBEngine: validate/load original psh, map guest segments/import stubs
  -> GuestCPU: bounded 32-bit ARMv6 ARM/Thumb calls and guest memory
       original GameManager, player/enemy/scenario/collision/menu/save code
       |-- known stub/function bridges -> native memory, math, audio and files
       |-- guarded geometry hooks -> dimension-dependent original state
       |-- original draw order/state -> ordered triangles and texture sampling
  -> Metal offscreen target -> matching drawable blit and present
     or software raster -> immutable CoreGraphics frame -> SwiftUI leaf
  -> native audio control queue + real-time mixer callback
  -> original PSH0 bytes -> isolated local save coordinator
                          -> optional KVS or Files-based progress exchange
```

**SOURCE** Native calls enter functions with guest addresses and register words. The low address bit selects Thumb, `r0–r3` carry arguments including float bit patterns, extra words go on an eight-byte-aligned guest stack, and a nested bridge call restores the enclosing register/flag context while retaining intended memory changes. The interpreter models NZCV, pipeline-relative PC reads, interworking and original inline switch helpers. It bounds its address space at 32 MiB and the default call at 2,000,000 steps. Unsupported opcodes/imports stop with a diagnostic. That bound is a containment policy, not an ISA conformance claim. [S-CPU] [S-ENGINE]

**SOURCE** The bridges use original 32-bit heap/list layouts, floating-point ABI helpers, strings, fixed-function draw state, original sound effects and a narrow file contract. The original `GameManager::update` entry is `0x8af3`, render is `0x8b23`, and the touch move call `0x8b77` passes current x/y and previous x in registers, previous y on the stack. Rendering compatibility and file/audio services are native replacements for old APIs. The three geometry instructions and the specific Credits rendering substitution are narrow native replacements in guest dispatch. Haptic event taps observe original boundaries and normally let the guest instructions continue. The startup texture data, Options rows and version label are host-maintained data adaptations. None replaces the guest's enemy logic, collision, movement integrator or save packing. [S-ENGINE] [S-GEOMETRY]

**SOURCE** Ordinary non-Watch hosts use Metal when supported, with the software path available via `SDB_CPU_RENDERER`. Watch uses software. SwiftUI observes software frame publication at a leaf. The software menu cache ships, while its force-uncached comparison switch is compiled only in the headless harness. `SDB_PERFORMANCE_LOG=1`, muted test audio, injected save locations and isolated TV test defaults are opt-in diagnostics. Personal Xcode configurations select provisioned KVS. The unsigned iOS Release override selects optional Files access. A usable local save does not require either transport. [S-SESSION] [S-ENGINE] [S-METAL] [S-CONFIG] [S-SIDELOAD]

**SOURCE** The prepared guest executable, its original texture/audio assets, layout data and menu behavior come from the supplied archive. The C++ interpreter and native bridges are project-maintained. Respring supplied the workflow and release precedents. No vendored touchHLE runtime, Rust/SDL compatibility bundle or translated gameplay corpus appears in the audited Space Deadbeef source/package. The optional xBRZ 1.9 scaler is an offline, hash-pinned preparation dependency. Its standalone tooling carries GPL-3.0 terms, and only its image outputs enter app resources. New title extensions and icon art are separately attributed as derived work. [S-SCALER-LICENSE] [S-SHIP] [S-SPRITES]

## 5. Fixes and investigations

### 5.1 Entering the original game on a current host

**SOURCE / INFERENCE** The input was a 32-bit iPhoneOS 2.1 executable with an old UI, draw, and audio stack. A normal modern app launch could not load its ARMv6 slice. The starting hypothesis was that the retained C++ gameplay below the UIKit wrapper had a smaller compatibility surface than the original app shell. The discriminating reproduction starts with exact prepared assets, initializes textures and the original sound singleton before GameManager, enters Options, then invokes actual Game Start and ordinary held/drag/release input. Launching a native shell alone would miss guest pointer width, ABI, import or initialization failures. No chronological first-fault log survives in the report evidence. [S-INTAKE] [S-ENGINE] [S-RUNTIME-TEST]

**SOURCE** Intake pins the archive and executable separately. It rejects duplicate entries, ZIP traversal, symlinks, more than 1,000 entries, over 500,000,000 expanded bytes, or any entry over 100,000,000 bytes. It copies guest code and WAVs and normalizes CgBI PNGs by reversing raw deflate, row filters, channel order and premultiplication as needed. At runtime `loadOriginal` rejects a different executable SHA-256 before segment mapping or hook dispatch, requires a manifest and bounded load commands and resolves `__symbol_stub4` through the indirect symbol table. Guest pointers stay in bounded guest memory. Relevant ABI details include ARM/Thumb PC and link rules, an 8-byte call stack alignment, bounds-checked indirect memory, and Apple's `*vfp` comparison helper predicates. Substituting a generic libgcc three-way comparison would change branch decisions for the same operands. [S-INTAKE] [S-ENGINE] [S-CPU]

**RECORD** `script/test_runtime.sh` and the retained headless smoke cover original Start, move/cancel, natural deaths, isolated PSH0 writes and Continue in a fresh engine. A baseline 3,600-update active-input run executed 105.3 million counted guest steps with no instruction/import fault in that run. Later CPU fast-path validation recorded 376 sanitizer checks and 496,608 matched baseline/current states, including every 16-bit Thumb word in three starting states. It compared registers, flags, memory, fault outcomes and step counts. Deliberately unsupported instructions and out-of-range accesses are discriminators. They are expected to fault. Neither exhaustive instruction-word enumeration in finite states nor a successful round establishes all instruction or gameplay paths. [S-CPU-TEST] [S-RUNTIME-TEST]

**INFERENCE** Use the prior interpreter and original-aspect tag as the fallback for a changed CPU fast path. Treat another edition, encrypted input, different stub table or hard-float ABI as a new intake. Port its calling convention and proven reachable imports before reusing addresses. Exception registration stubs and strict faults have only the narrow support described in §6. [S-BASE] [S-CPU]

### 5.2 Fixed-function graphics on Metal and software

**SOURCE / INFERENCE** The original renderer is a sequence of stateful GL ES 1 calls. Hooking only the high-level sprite draw would miss matrix nesting, vertex-colored primitives, lines, atlas subregions and additive effects. Tests therefore reproduce the actual Start frame and independent overlap, alpha and color fixtures. The baseline was the original-aspect software renderer. Its 320×480 guest math and clockwise landscape presentation provided a parity oracle for native Metal. [S-BASE] [S-ENGINE] [S-RENDER-TEST]

**SOURCE** `SDBEngine` preserves matrix transforms, primitive order, texture padding and normalized UVs, REPLACE (`0x1e01`) versus MODULATE (`0x2100`), and original blend factors `0`, `1`, `0x302`, `0x303`. The original table has 62 records of 32 bytes, 61 populated texture slots and unused slot 45. Its metadata retains original content/padded dimensions and UV limits. The bridge bounds an individual draw at 4,096 vertices. The Metal renderer validates draw ranges, texture references, triangle divisibility, blend factors and raster limits before encoding. It targets an offscreen BGRA8 surface and blits to a same-size, same-format, single-sample drawable that permits the blit. `MetalGameSurface` synchronizes the drawable to engine raster dimensions and skips presentation while they disagree. Watch uses the software path. [S-ENGINE] [S-METAL] [S-SURFACE]

**RECORD** Later `script/test_rendering.sh` retained eleven software/actual Mac GPU fixture comparisons within one byte. Transparent overlap, replacement vs modulation and nonzero initial vertex offsets distinguish visually plausible but incorrect frames. The build-10 suite also tested a deliberately missing compiled shader library. Both GPU fixtures failed instead of classifying the result as an unavailable-device skip. The real Metal workload compared sampled readbacks on one Mac. Its portable golden check intentionally excludes GPU pixel hashes because rounding differs across drivers. Full GL ES, device scanout and pixel identity against a physical original remain **UNVERIFIED**. [S-RENDER-TEST] [S-EQUIV] [S-HOST-NOTES]

**INFERENCE** Retain an independent software renderer or trusted frame capture as a parity oracle. Preserve renderer path choice and only compare equivalent raster and color state. A full command queue retains the previous valid output. That is an expected backpressure case distinct from an invalid drawable or library failure. Verify both on the target host before assuming another GL bridge is equivalent. [S-METAL] [S-SURFACE]

### 5.3 Adaptive arenas, inverse input and safe-area controls

**OBSERVATION / SOURCE** The working aspect-fit build left bars on contemporary screens. Merely drawing scenery in the bars would not change the ship's travel, enemies' entrances or the location a touch selects. Original guest coordinates use centered portrait axes and the game owns its 180-degree camera inversion. Original portrait touch used `x=pointX−160, y=240−pointY`. In the restored landscape coordinate system, host logical point `(x,y)` maps to guest `(y−height/2, x−width/2)`. The inverse reverses the same swap and translation. Resize reproduction includes a wider phone, taller Watch/iPad, asymmetric insets, Duo folding/rotation and Mac window resize while the game remains live. The UI defect at narrow widths was overlapping high-score digits and the charge cells. On iPad, the system status area initially covered the physical-corner pause control. [S-GEOMETRY] [S-RENDER-NOTES]

**SOURCE** `DisplayGeometry` keeps one logical landscape dimension at 480×320 baseline scale while expanding the other, separates safe UI points and device raster, and provides the inverse guest input map. Raster scale is clamped to 1–3× before size limits of 8,192 per axis and 16,777,216 pixels. `GameDisplayPatch::initialize` validates original float words including HUD metrics, fingerprints the route (`0x11c88–0x12a68`), menu (`0x14688–0x14f70`) and coordinate (`0x12b30–0x12b50`) tables, checks waypoint types/terminators, and checks the original Options pointer. Three Thumb halfwords must be `0x491a` at `0x5a3c`, `0x4a2b` at `0xc5ba` and `0x609a` at `0xc5ce`. Each handler rechecks Thumb state, initialized baseline, opcode and the bounded store where applicable. It preserves flags and advances PC by two. Patch writes derive from immutable original values and are prepared before application. Offscreen spawn margins retain their signed distance beyond the new edge. [S-GEOMETRY] [S-DISPLAY-PATCH] [S-DISPLAY-TEST]

**SOURCE / RECORD** HUD compression removes original blank gaps before touching ink metrics. Watch retains the original glyphs and full gauge in a centered, low HUD and uses a 26-point visible top-left corner fold with a larger native tap area. The iOS corner control uses the real screen edge, separate artwork and native hit target, and calls the original pause callback. The version label remains relative to the title artwork. iPad uses availability-gated status-bar hiding. The recorded Duo/iPad pass reports 7,423 patch and 4,712 geometry assertions, with bad fingerprints, invalid safe bounds, inverse map, non-Watch restoration and original aspect as counterexamples. Seven viewport smoke cases used a live engine and real Pause/Continue. Duo folding and iPad portrait/landscape/Stage Manager were visibly exercised in Simulator. The observed tested HUD ink lower bound is 349.67 logical safe units. Continuous physical fold/resize and narrower cases are **UNVERIFIED**. Initial Duo headless screenshots were black, so visual confirmation came from the active Simulator view. E-DISPLAY and E-WATCH. [S-DISPLAY-TEST] [S-VIEWPORT-TEST] [S-HOST-VIEW] [S-PAUSE]

**INFERENCE** A port should retain a verified original-aspect configuration for rollback. If exact geometry guards fail, stop that patch for the unsupported image. Re-derive tables, the guest camera transform, original glyph metrics and corner hit regions before adapting another game. Asymmetric insets, repeated resize back to the original dimensions, and a touch just inside/outside a boundary are more discriminating than a static title capture. [S-BASE] [S-DISPLAY-TEST]

### 5.4 Title joins and tight bitmap glyphs

[S-RENDER-NOTES]

**SOURCE** Title extension is drawn separately behind the original composition. The simplified margins use a short blended transition and continue the original local colors/cloud. Texture-border normalization and padded sampling address seams. Tall gameplay background uses uniform cover before the original camera transform. Baked title label foreground/shadow use separate fields where prepared. Dynamic small font uses the larger original atlas with the same grid and guest metrics. This guard matters when the first vertex is 7 rather than a multiple of 3. [S-ENGINE] [S-SHADERS] [S-RENDER-NOTES]

**RECORD** The font pass retained ten software/Mac GPU comparisons within one byte, including fractional UVs, original large/small alpha and a synthetic neighboring-cell bleed case. iPhone Simulator and native Mac Credits/Options were visually inspected. Source-art shadow edges were preserved. The added scenery and cleaner edges cannot establish any recovered historical detail. Later visual audits remain limited to the captured views. [S-RENDER-TEST] [S-RENDER-NOTES]

Revert only the added margins or font sampling path if the original composition is affected. [S-SHADERS] [S-RENDER-TEST]

**SOURCE / RECORD** The original Credits included a nonexecutable contact row. The exact-image guard at row `0x1482c` verifies the original text, the word 62 at row offset 32, zero callback and glyph metrics. A native link appears only in settled Credits on supported hosts. ### 5.5 Higher-density sprites and separate launcher artwork

**OBSERVATION / RECORD** The player's entrance flyby magnifies the 128×128 ship art, exposing raster limits despite a high-density framebuffer. Its 1024-scale sky was undersized for the 1088-point Watch composition. [S-SHIP] [S-SPRITES] [S-ICON]

**SOURCE** The offline tools scale the 25 ship views and 16 additional gameplay textures at 2× for Watch and 4× for Metal hosts. The engine validates exact original name, slot and logical dimensions (ship slots 12–36 and gameplay slots 46–61), then requires decoded size equal to original × density. A wholly missing density directory uses original assets. A present incomplete set faults, which avoids mixing viewpoints or effect frames. Native POT padding expands proportionally while the guest keeps original dimensions, IDs and UV bounds. Hard contours use pinned xBRZ 1.9 ARGB. Five soft-effect sprites use bilinear RGBA. All 98 of these atlas cells are exported separately into the same scaled positions, a geometry count distinct from the package's 98 prepared-original files. [S-SHIP] [S-SPRITES] [S-ENGINE]

**RECORD** Actual loader tests recorded 205 ship and 408 other sprite checks. They exercise both densities, partial-set rejection, original-only fallback and guest UV/size parity. Paired 600-step runs matched guest-state, draw, audio and save fingerprints while images differed as intended. Equal-size crops from 1704×786 actual-engine renders showed the same near-camera entrance frame. iPhone Simulator gameplay confirmed the visible path. The ship and other sprite sets together add about 9.16 MiB of decoded Watch CPU textures or about 45.81 MiB on the other hosts, before Metal uploads. **INFERENCE** Keep original assets authoritative and preserve a no-derivative fixture. Require animation registration and alpha-edge checks, per-cell bounds, close-up and normal gameplay views before transfer. For a regressed launcher, restore the proven catalog/layout independently of gameplay. [S-ICON] [S-SHIP]

### 5.6 Frame-path stalls, render submission and software cadence

**OBSERVATION / RECORD** On the pre-performance 1.1 branch the player reported stutter. Matched Mac sampling and Time Profiler implicated repeated import-name conversion, checked-memory overhead and audio preparation/transport work on the frame path. A persistent AVAudioPlayerNode prototype still spent up to 10.609 ms on a play request in the recorded comparison. The later pass found software color pattern fills and repeated Metal state/encoding work.
